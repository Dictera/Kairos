Open `drizzle/0002_phase14_avukat_schema.sql` and verify it contains:

- `ALTER TABLE `sigorta_sirketi` ADD `bagli_oldugu_vergi_dairesi` text;`
- `ALTER TABLE `sigorta_sirketi` ADD `ihtar_mail` text;`
- `ALTER TABLE `sigorta_sirketi` ADD `kep_mail` text;`
- `CREATE TABLE `avukat` (...);` with 8 columns including `created_at` / `updated_at` defaults of `(datetime('now'))`
- `CREATE TABLE `avukat_sigorta_sirketi` (...);` with 2 FK columns + ON DELETE CASCADE on both
- Three indexes: `idx_avukat_sirketi_avukat`, `idx_avukat_sirketi_sirketi`, `uniq_avukat_sirketi`
- `ALTER TABLE `taraf` ADD `avukat_id` integer REFERENCES `avukat`(`id`)...;` (with ON UPDATE no action ON DELETE set null per Plan 01 schema declaration)

If drizzle-kit emits a table-recreate pattern for `taraf` instead of `DROP COLUMN` (it sometimes does this for FK changes), that is also acceptable — the end state is equivalent. Do NOT hand-edit the SQL unless the `vergi_no DEFAULT ''` is missing (in which case add it before the `NOT NULL`).
