<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User → .env configuration | Environment variable paths could point to malicious binaries |
| tRPC API → Python sidecar | Subprocess spawn with user-controlled paths is injection vector |
| Python stderr → Node.js logs | Structured logs from sidecar should not be leaked to client |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-01 | Tampering | config.ts path detection | mitigate | Validate binary paths exist and are executable via `fs.access` before spawning; never use shell mode in execa |
| T-15-02 | Tampering | docx-pipeline.ts execa call | mitigate | Always use array arguments with execa (never shell mode); use `reject: false` to handle exit codes gracefully |
| T-15-03 | Denial of Service | health-check.ts sidecar invocation | mitigate | Set 10-second timeout on health check execa calls; 30-second on general commands per D-07 |
| T-15-04 | Information Disclosure | docx-pipeline.ts stderr | accept | stderr contains JSONL structlog lines for server-side debugging only; tRPC never exposes stderr to client |
| T-15-05 | Tampering | .env PYTHON_PATH override | mitigate | Per D-10, .env.local value overrides; config.ts validates path existence before use |
</threat_model>
