## Interaction Contracts

### Upload Flow
1. User clicks "Şablon Yükle" → Dialog opens
2. User fills ad + kategori + selects .docx file
3. Client validates: `.docx` extension, ≤10MB, ad non-empty, kategori selected
4. On submit: file uploaded to `/api/templates/upload` → returns `filePath`
5. tRPC `sablon.create` mutation called with `{ad, kategori, filePath}`
6. Server calls sidecar `extract-vars` → saves to DB
7. On success: toast "Şablon yüklendi.", dialog closes, table refreshes
8. On error: toast with error message, dialog stays open, file cleared

### Overwrite Flow
1. User clicks Upload icon on existing template → Dialog opens with "Şablonu Değiştir" title
2. User selects new .docx file (ad and kategori pre-filled, read-only)
3. On submit: new file uploaded → tRPC `sablon.update` → re-extracts variables
4. Same DB ID preserved; `belge.sablon_id` references stay valid (D-06)

### Delete Flow
1. User clicks Trash2 icon → AlertDialog opens
2. User confirms "Evet, Sil"
3. tRPC `sablon.delete` → SET NULL on `belge.sablon_id`, removes file from disk
4. On success: toast "Şablon silindi.", table refreshes

### Category Filter
- Dropdown at top of table, client-side filtering
- Default: "Tüm Kategoriler" (shows all)
- Selecting a kategori filters table rows immediately (no server round-trip)
