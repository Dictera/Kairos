# Milestone v1.2: Şablon Belgeler

**Status:** ✅ SHIPPED 2026-04-22
**Phases:** 15–20
**Total Plans:** 21

## Overview

Avukatın kendi `.docx` şablonlarını yüklediği, dosya detayındaki tüm verilerle otomatik doldurulan, Python sidecar + LibreOffice headless üzerinden PDF üreten tek doğru belge pipeline'ını kurmak; iki eski sistemi (Tiptap editör + .odt upload) kod ve veriyle birlikte kaldırmak.

## Phases

**Depends on**: Nothing (v1.2 foundation — builds on existing v1.1 Next.js/Drizzle app)
**Plans**: 2 plans

Plans:

- [x] 15-01: Python sidecar + TypeScript infrastructure (config, protocol, error codes, health check, execa bridge, tRPC router)
- [x] 15-02: Pipeline UI (health banner, status card, layout and settings integration)

**Details:**
- Python sidecar (`scripts/docx-pipeline/`) with pydantic v2, docxtpl, jinja2, babel, python-slugify, structlog, tenacity
- JSON stdin/stdout IPC protocol with pydantic CommandEnvelope

- HealthBanner (amber warning on all dashboard pages when Python/LibreOffice missing)
- PipelineStatus card (Ayarlar page showing Python/LibreOffice path, version, accessibility)

**Depends on**: Phase 15 (sidecar) + Phase 16 (şablon + değişken listesi)
**Plans**: 4 plans

Plans:

- [x] 17-01: Python sidecar render & convert (filters.py, convert.py, handle_render/handle_convert)
- [x] 17-02: TypeScript protocol extension + variable registry with tab mapping
- [x] 17-03: pdfRouter + Jinja2 context builder + missing-variable pre-check
- [x] 17-04: Integration test: canary template with Turkish chars end-to-end

**Details:**
- TR custom Jinja2 filters: tr_currency (tr_TR locale), tarih (dd.MM.yyyy), upper_tr, lower_tr (Turkish i↔İ)

- Per-invocation temp profile: `-env:UserInstallation=file:///TEMP/lo-{uuid}`
- Variable registry (`lib/docx/variable-registry.ts`) with tab mapping for missing-var pre-check
- pdfRouter.generate with context builder from Drizzle relations

**Depends on**: Phase 17 (PDF üretimi olmadan arşive girdi yok)
**Plans**: 3 plans

Plans:

- [x] 18-01: Schema migration, sidecar slug command, and sablon router belge_turu support
- [x] 18-02: Archive module with compensating transaction and unit tests
- [x] 18-03: pdfRouter archive integration and template UI belge_turu dropdown

**Details:**
- belge_turu nullable column on docx_sablon for document categorization

- Slug-based filename: `{müvekkil-slug}-{plaka-slug}-{seq}.pdf`
- Archive path: `./uploads/sablon-pdf/YYYY/AA/{kategori-slug}/`

## Milestone Summary

**Key Decisions:**

- JSON stdin/stdout IPC over named pipes or socket — simpler debugging, works across platforms
- Module-level singleton pattern for health cache (same as db.ts singleton pattern)
- Pre-transliterate Turkish chars before python-slugify for consistent ASCII output across environments
- Nullable text column for belge_turu rather than enum constraint at DB level
- Non-dismissible Dialog for progress modal (onInteractOutside + onEscapeKeyDown preventDefault)
- DROP TABLE IF EXISTS for safe idempotent legacy table removal

**Issues Resolved:**

- Windows stdin encoding in verification (Python subprocess with Turkish chars on Windows)
- TypeScript circular inference error on selected state type (used explicit inline type)
- Race condition in seq calculation (replaced with UUID filename suffix)
- Turkish Lira symbol placement (150.000,00 ₺ → 150.000,00 TL with ₺ at end)

**Issues Deferred:**

- Debug session "dilekce-odt-olustur-pdf-onizleme" superseded by v1.2 retirement
- Pre-existing tsc errors in archive.test.ts, pipeline.test.ts, config.test.ts (unrelated to v1.2)

**Technical Debt Incurred:**

- Stale template variable reference in karsitaraf_vekil (Phase 14, replaced by avukat FK)
- Drizzle journal tag mismatch (journal entry tag doesn't match migration filename prefix)
