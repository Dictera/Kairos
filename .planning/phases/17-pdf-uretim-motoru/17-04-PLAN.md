  <name>Task 1: Create canary template fixture and integration test</name>
  <files>scripts/docx-pipeline/test_integration.py, scripts/docx-pipeline/fixtures/canary-template.docx</files>
  <action>
    Create `scripts/docx-pipeline/test_integration.py` that performs an end-to-end test:

    1. **Create fixture directory:** Ensure `scripts/docx-pipeline/fixtures/` exists.

    2. **Build canary template programmatically:** Use `python-docx` (already available as docxtpl dependency) to create `scripts/docx-pipeline/fixtures/canary-template.docx` with the following content:
       - A paragraph: `Müvekkil: {{ muvekkil.ad | upper_tr }} {{ muvekkil.soyad | upper_tr }}`
       - A paragraph: `Karşı taraf: {{ taraf.karsitaraf_ad | lower_tr }}`
       - A paragraph: `Tutar: {{ dosya.talep_tutari | tr_currency }}`
       - A paragraph: `Tarih: {{ dosya.kaza_tarihi | tarih }}`
       - A paragraph with conditional: `{% if durusmalar %}Duruşma var{% else %}Duruşma yok{% endif %}`
       - A paragraph with loop: `{% for d in durusmalar %}{{ d.mahkeme_kurum }} — {{ d.tarih | tarih }}{% endfor %}`
       - A paragraph with Turkish chars directly in template text (not variables): `çÇğĞıİöÖşŞüÜ İstanbul şirket müvekkil`

       IMPORTANT: When inserting Jinja2 tags via python-docx, use `doc.add_paragraph()` with the raw tag strings. python-docx does not interpret Jinja2 — it just writes the text into the DOCX XML, which docxtpl will later process.

    3. **Build test context:**
       ```python
       context = {
           "muvekkil": {"ad": "ahmet", "soyad": "ışık"},
           "dosya": {"dosya_no": "2026/42", "talep_tutari": 150000, "kaza_tarihi": "2026-02-14"},
           "taraf": {"karsitaraf_ad": "MEHMET ÇELİK"},
           "durusmalar": [
               {"tarih": "2026-03-15", "mahkeme_kurum": "İstanbul Adliyesi"}
           ],
           "stk": {},
           "mahkeme": {},
           "sureler": [],
           "finans_kalemleri": [],
           "notlar": [],
       }
       ```

    4. **Call render:** Build a `CommandEnvelope` JSON for `command: "render"` with:
       - `template_path`: absolute path to canary-template.docx
       - `output_path`: `os.path.join(tempfile.gettempdir(), "canary-rendered.docx")`
       - `context`: the test context above
       - Pipe JSON to `python main.py` via stdin (same pattern as Node.js sidecar IPC)
       - Assert stdout parses as JSON with `status == "success"`

    5. **Call convert:** Build a `CommandEnvelope` JSON for `command: "convert"` with:
       - `input_path`: the rendered DOCX path from step 4
       - `output_dir`: `tempfile.gettempdir()`
       - `libreoffice_path`: read from environment variable `LIBREOFFICE_PATH` or use platform default (`soffice` on PATH, or `C:\Program Files\LibreOffice\program\soffice.exe` on Windows)
       - `timeout`: 120
       - Pipe JSON to `python main.py` via stdin
       - Assert stdout parses as JSON with `status == "success"`
       - Assert the returned `output_path` file exists and has `.pdf` extension

    6. **Verify PDF text content:** Use `PyPDF2` or `pdfplumber` to extract text from the generated PDF and assert it contains:
       - `"AHMET IŞIK"` (upper_tr result)
       - `"mehmet çelik"` (lower_tr result)
       - `"150.000,00"` (tr_currency result, contains the amount)
       - `"14.02.2026"` (tarih result)
       - `"Duruşma var"` (conditional block worked)
       - `"İstanbul Adliyesi"` (loop worked)
       - `"çÇğĞıİöÖşŞüÜ"` (Turkish characters preserved through render+convert)

       If `PyPDF2`/`pdfplumber` are not installed, the test can skip the text-extraction assertions and only verify file existence + size > 0, but print a WARNING that text extraction was skipped.

    7. **Cleanup:** In a `finally` block, delete the rendered DOCX and the generated PDF using `os.unlink()` (ignore errors).

    The test script should exit with code 0 on success and code 1 on any assertion failure.
