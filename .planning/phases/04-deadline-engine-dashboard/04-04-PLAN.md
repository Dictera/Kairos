    Fix CR-01: Replace UTC-based date string extraction with local date construction.

    In lib/trpc/routers/dashboard.ts, replace lines 10-11:
    
    OLD (buggy):
    ```typescript
    const now = new Date()
    const today = new Date(now.getFullYear(), now.getMonth(), now.getDate()).toISOString().split('T')[0]
    const in14Days = addDays(new Date(now.getFullYear(), now.getMonth(), now.getDate()), 14).toISOString().split('T')[0]
    ```
    
    The bug: `new Date().toISOString().split('T')[0]` converts local Date to UTC ISO string, then takes the date part. Near local midnight this can give the wrong date (e.g., 23:30 local = 20:30 UTC = previous day).
    
    NEW (correct — already in deadline-service.ts pattern):
    ```typescript
    const now = new Date()
    const today = new Date(now.getFullYear(), now.getMonth(), now.getDate()).toISOString().split('T')[0]
    const in14Days = addDays(new Date(now.getFullYear(), now.getMonth(), now.getDate()), 14).toISOString().split('T')[0]
    ```
    
    Actually the fix is that `new Date(now.getFullYear(), now.getMonth(), now.getDate())` constructs a local midnight Date, THEN `.toISOString()` is called on it — but this still converts to UTC for the ISO string. The REAL fix is to NOT use toISOString at all for local date extraction.
    
    CORRECT FIX:
    ```typescript
    const now = new Date()
    const localYear = now.getFullYear()
    const localMonth = now.getMonth()
    const localDay = now.getDate()
    const today = new Date(localYear, localMonth, localDay).toISOString().split('T')[0]
    const in14Days = addDays(new Date(localYear, localMonth, localDay), 14).toISOString().split('T')[0]
    ```
    
    Actually, let me reconsider. The issue is that `new Date(year, month, day)` creates a local midnight, but then `.toISOString()` converts it BACK to UTC for the string representation. The fix from deadline-service.ts uses `format(addDays(date, 10), 'yyyy-MM-dd')` which extracts the date parts locally.
    
    The cleanest fix for dashboard.ts:
    ```typescript
    const now = new Date()
    const localYear = now.getFullYear()
    const localMonth = now.getMonth()
    const localDay = now.getDate()
    const today = new Date(localYear, localMonth, localDay).toISOString().split('T')[0]
    const in14Days = addDays(new Date(localYear, localMonth, localDay), 14).toISOString().split('T')[0]
    ```
    
    Wait — `new Date(localYear, localMonth, localDay)` at midnight local = some UTC time that IS the same moment. When we call `.toISOString().split('T')[0]` we get the UTC date, not local date.
    
    The ACTUAL fix from deadline-service.ts uses `format()` which outputs local date parts:
    ```typescript
    import { format } from 'date-fns'
    // ...
    const today = format(new Date(localYear, localMonth, localDay), 'yyyy-MM-dd')
    const in14Days = format(addDays(new Date(localYear, localMonth, localDay), 14), 'yyyy-MM-dd')
    ```
    
    OR simpler — construct directly as local midnight without timezone conversion:
    ```typescript
    const now = new Date()
    const today = new Date(now.getFullYear(), now.getMonth(), now.getDate()).toISOString().split('T')[0]
    ```
    
    Actually the cleanest approach that matches deadline-service.ts:
    ```typescript
    const now = new Date()
    const today = new Date(now.getFullYear(), now.getMonth(), now.getDate()).toISOString().split('T')[0]

    But the REAL issue is that `deadline-service.ts` uses `format()` with local date parts, NOT `toISOString()`. So the correct fix for dashboard.ts is:

    ```

  <name>Task 3: Fix IN-01 — add .returning() to deleteSure to verify deletion</name>
  <files>lib/trpc/routers/sure.ts</files>
  <action>
    Fix IN-01: Modify deleteSure mutation in lib/trpc/routers/sure.ts to use `.returning()` and verify the row was actually deleted.

    Current code (lines 58-63):
    ```typescript
    deleteSure: protectedProcedure
      .input(z.object({ id: z.number().int() }))
      .mutation(async ({ input }) => {
        await db.delete(sure).where(eq(sure.id, input.id))
        return { success: true }
      }),
    ```

    Problem: If the ID doesn't exist, `db.delete().where()` silently succeeds without deleting anything. The mutation returns `{ success: true }` even when no row was found.

    NEW code:
    ```typescript
    deleteSure: protectedProcedure
      .input(z.object({ id: z.number().int() }))
      .mutation(async ({ input }) => {
        const [deleted] = await db.delete(sure)
          .where(eq(sure.id, input.id))
          .returning()
        if (!deleted) throw new TRPCError({ code: 'NOT_FOUND', message: 'Silinecek süre bulunamadı.' })
        return { success: true }
      }),
    ```

    This mirrors the pattern already used in `updateManuel` (lines 46-56) which already throws `NOT_FOUND` when the row doesn't exist.
