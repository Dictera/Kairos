## Color

All colors are sourced from `app/globals.css` CSS custom properties. Do not hardcode hex values — use Tailwind semantic classes (`bg-background`, `text-foreground`, etc.).

| Role | CSS Variable | Approximate Hex | Usage |
|------|-------------|----------------|-------|
| Dominant (60%) | `--background` | #F5F0E8 (warm beige) | Page background, dashboard surface |
| Secondary (30%) | `--card` | warm white | Stat cards, deadline widget container, hearing widget container |
| Accent (10%) | `--accent` | #1C768F (steel blue) | Dosya no links in deadline rows, "Manuel Süre Ekle" button outline variant |
| Primary | `--primary` | #FA991C (orange) | CTA buttons (save deadline), focus ring |
| Destructive | `--destructive` | red (oklch 0.577 0.245 27) | Süre silme confirmation dialog destructive button only |
| Sidebar | `--sidebar` | #032539 (navy) | Already established — no changes in this phase |

Accent reserved for:
1. Dosya no link text in deadline list rows (`text-accent`)
2. Müvekkil name link text in deadline list rows (`text-accent`)
3. "Manuel Süre Ekle" button — `variant="outline"` with accent border
4. Today's hearing row links to case detail

Do NOT use accent for: badge fills, urgency indicators, headings, or stat card values.

### Urgency Badge Colors

These are semantically separate from the 60/30/10 palette and come from REQUIREMENTS.md DASH-02 and CONTEXT.md D-03:

| State | Tailwind Class | Condition |
|-------|---------------|-----------|
| Critical (red) | `bg-destructive text-destructive-foreground` | daysUntil < 3 |
| Warning (yellow) | `bg-yellow-400 text-yellow-900` | daysUntil >= 3 AND < 7 |
| Neutral (grey) | `bg-muted text-muted-foreground` | daysUntil >= 7 AND <= 14 |
| Overdue | `bg-destructive text-destructive-foreground` | daysUntil < 0 |

Use shadcn `<Badge>` component (`components/ui/badge.tsx`) for all urgency indicators.

### Adli Tatil Badge

Separate from urgency badges. Inline, non-blocking. Always amber/warning tone regardless of urgency.

```
bg-amber-100 text-amber-800 border border-amber-300
```

Text content: `⚠ Adli Tatil — manuel kontrol` (per D-05 from CONTEXT.md)

## Layout Contract

Source: CONTEXT.md D-01, D-02, and the mockup in `<specifics>`.

### Dashboard Page (`app/(dashboard)/page.tsx`)

Three-section vertical stack. Full width, single column. No sidebar overlap.

```
┌─────────────────────────────────────────────┐
│  [Stat Card: Toplam]  [Aktif]  [Bu Ay]      │  <- 3-col grid, gap-lg
├─────────────────────────────────────────────┤
│  Card: Yaklaşan Süreler                     │  <- mt-xl
│    [badge] Süre adı   Müvekkil — #Dosya  N gün [adli tatil?]
│    ...                                      │
├─────────────────────────────────────────────┤
│  Card: Bugünkü Duruşmalar                   │  <- mt-xl
│    HH:MM — Mahkeme kısa — Dosya #N link    │
│    ...                                      │
└─────────────────────────────────────────────┘
```

- Stat cards: `grid grid-cols-3 gap-6`
- Each section wrapped in `<Card>` with `<CardHeader>` + `<CardContent>`
- Dashboard is read-only — no forms, no buttons except row links (D-02)

### Manual Deadline Form (Case Detail Page — Süreler Subsection)

Located in Yargılama Süreci tab, below process data fields. Uses `react-hook-form` + Zod resolver (established pattern from Phase 2/3).

Fields:
1. **Süre Adı** — `<Input>` text, required, max 100 chars
2. **Son Tarih** — `<Input type="date">`, required
3. **Notlar** — `<Textarea>` optional, max 500 chars
4. **Kaydet** — `<Button type="submit">` primary variant

Success: sonner toast "Süre kaydedildi" (established pattern).

## Interaction Contract

### Loading States

- Dashboard initial load: Show `<Skeleton>` for all three sections simultaneously while `dashboard.stats` tRPC query resolves.
- Skeleton for stat cards: 3 × card-shaped skeleton, same grid layout.
- Skeleton for lists: 3 rows of skeleton lines per widget.

### Error States

- If `dashboard.stats` query fails: Show a single full-width error card with copy "Veriler yüklenemedi. Sayfayı yenileyiniz." — no retry button (simple page refresh expected).
- If manual deadline form fails server mutation: sonner toast error "Süre kaydedilemedi. Tekrar deneyin."

### Optimistic Updates

- Do NOT use optimistic updates for deadline CRUD in this phase. Wait for server response before updating UI. Simple enough data flow.

### Auto-Calculation (D-07)

- No UI feedback for auto-calc. The existing form save toast covers it. Do not add secondary "süre hesaplandı" toast.
- The `sure` table row appears in the dashboard on next load automatically.

### Navigation

- Deadline row click: navigate to `/dosyalar/[id]` (the case detail page). Full link, not a button.
- Hearing row click: navigate to `/dosyalar/[id]`. Full link.
- Stat cards: no navigation. Display only.
