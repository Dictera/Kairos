## Interaction Contracts

### DatePickerField

| Aspect | Contract |
|--------|----------|
| Trigger | Button `variant="outline"` with `CalendarIcon` right-aligned |
| Container | Popover, `align="start"`, `w-auto p-0` |
| Calendar mode | `mode="single"` |
| Locale | `locale={tr}` from `date-fns/locale/tr` |
| Week start | `weekStartsOn={1}` (Monday — Turkish standard) |
| Date format display | `format(date, 'dd.MM.yyyy', { locale: tr })` |
| Date format value | `yyyy-MM-dd` (ISO 8601, stored in DB) |
| Caption layout | `captionLayout="label"` (shows month/year in header) |
| Selected day | Turuncu `oklch(0.746 0.174 57)` via `[data-selected-single=true]` CSS |
| Placeholder text | `"Tarih seçin"` (default) or prop-provided |

| Aspect | Contract |
|--------|----------|

| Navigation buttons | Default shadcn button styling |
| Disabled dates | Muted opacity, `not-allowed` cursor |
| Range middle | Not used in this phase (`mode="single"`) |

## Phase-Specific Technical Notes

- **Prop correction:** Context document D-03 says `startWeekOn={1}` but react-day-picker v9 API uses `weekStartsOn={1}`. Implementation must use `weekStartsOn={1}` — verified in `node_modules/react-day-picker/dist/esm/types/props.d.ts:448`.
- **CSS variable `--primary`:** Already set to `oklch(0.746 0.174 57)` in `app/globals.css` (Turuncu `#FA991C`). Calendar selected day `[data-selected-single=true]` uses this variable automatically.
- **Turkish locale `tr`:** Has `weekStartsOn: 1` internally, but react-day-picker requires explicit `weekStartsOn={1}` prop.
- **No new dependencies:** All required libraries (react-day-picker v9.14.0, date-fns v4.1.0) already installed.
