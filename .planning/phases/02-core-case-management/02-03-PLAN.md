# Plan 02-03: Dosya UI — List, Create/Edit Form, 6-Tab Detail Shell

## Objective

Build the complete Dosya (case file) management UI: a paginated, server-side filtered list with 7 locked columns and always-visible search+filter controls; a create/edit form on separate pages with all 8 fields including sigorta türü and müvekkil selects; and a 6-tab detail page where Genel Bilgiler and Karşı Taraflar are fully functional and the remaining 4 tabs show the locked placeholder. This satisfies DOSYA-01 through DOSYA-05.

## Requirements Addressed

- **DOSYA-01** — Create dosya with all fields (müvekkil select, tür, sigorta türü, dosya no, talep tutarı)
- **DOSYA-02** — Dosya list: <1s for 200+ records; server-side filtered query; search + filters
- **DOSYA-03** — 6-tab detail shell: Genel Bilgiler + Karşı Taraflar filled; 4 others placeholder
- **DOSYA-04** — Edit all fields; archive action with AlertDialog; delete action
- **DOSYA-05** — Counter-party fields (sigorta şirketi, karşı vekil, poliçe no) editable on case

  muvekkil_id: z.number({ required_error: 'Müvekkil seçimi zorunludur' }).int(),

  tur: z.enum(['STK', 'AT', 'AH'], { required_error: 'Dosya türü zorunludur' }),
  sigorta_turu_id: z.number().int().nullable().optional(),

Data fetching for dropdowns (parallel queries before form renders):

Form fields layout (max-w-2xl, space-y-4):
1. **Avukat Dosya No** (required *): text Input
2. **Müvekkil** (required *): Select — options from `muvekkilList.rows`, display: `${ad} ${soyad}`, value: `id.toString()`
3. **Dosya Türü** (required *): Select — options: "STK", "Asliye Ticaret" (AT), "Asliye Hukuk" (AH)
4. **Sigorta Türü** (required *): Select — options from `sigortaTuruList`, includes "Seçiniz" placeholder
5. **Karşı Sigorta Şirketi** (optional): Select — options from `sigortaSirketiList`, includes "Yok / Bilinmiyor" option

7. **Müvekkil Plaka No** (optional): text Input, placeholder "34 ABC 123"
8. **Açıklama** (optional): Textarea, rows=3

Action buttons: "Vazgeç" (ghost, router.back()) | "Kaydet" (primary)

On create success: `toast.success('Dosya başarıyla oluşturuldu.')` + `router.push('/dosyalar/' + row.id)`
On update success: `toast.success('Kaydedildi.')` + `router.push('/dosyalar/' + dosyaId)`
On CONFLICT error (duplicate dosya_no): show field-level error: `form.setError('dosya_no', { message: 'Bu dosya numarası zaten kullanılıyor.' })`
On other error: `toast.error('Kaydedilemedi. Lütfen tekrar deneyin.')`

  - Copy: "Bu dosya arşivlenecek. Arşivlenen dosyalar listede "Arşivlenmiş" olarak görünür ve tekrar aktif hale getirilebilir."

## Threat Model

| Threat | Severity | Mitigation |
|--------|----------|------------|
| Unauthenticated access to dosya data | High | All tRPC procedures use `protectedProcedure`; middleware guards all (dashboard) routes |
| SQL injection via search/filter inputs | High | All inputs validated by Zod (`z.string().max(100)`); queries use Drizzle parameterized bindings; `sql` template literal params are bound, not interpolated |
| Turkish character injection in LIKE | Medium | `lower_tr()` scalar normalizes both sides of LIKE before comparison; parameterized binding prevents injection even with Turkish special chars |
| Mass exposure via unlimited pageSize | Medium | `pageSize` capped at 100 in Zod; default 25; no unbounded query path |
| Dosya archive/delete without confirmation | Medium | Both archive and delete actions require AlertDialog confirmation in UI; server-side the mutations are idempotent but irreversible — delete cascades to taraf |
| Unauthorized taraf edit (wrong dosya_id) | Low | `upsertTaraf` validates `dosya_id` exists in DB via `getById` before update; single-user app with no cross-user data isolation needed |
| XSS via unsanitized case content | Low | All data rendered via React JSX (auto-escaped); no `dangerouslySetInnerHTML` in any dosya component |
