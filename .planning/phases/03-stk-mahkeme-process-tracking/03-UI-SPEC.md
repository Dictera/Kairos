**Muted (--muted-foreground):** form field placeholder text, duruşma list "—" empty cell values, connector lines between stepper dots.

## Interaction Contracts

### 1. Stepper — Stage Advancement

- Stepper renders as a horizontal ordered list for ≤9 stages.
- On mobile breakpoints (if ever needed): vertical stack. This phase targets desktop only.
- Each step node: 20px dot + stage label below in text-xs (12px) truncated to 8 chars max with full label in tooltip.
- "İleri Al →" button appears inline with the current stage node — positioned to the right of the ◎ dot.
- On click: optimistic UI update (stage dot changes to ● immediately), tRPC `ileriAl` mutation fires, sonner toast confirms on success or reverts on error.
- Button is disabled (cursor-not-allowed, opacity-50) when current stage is the final stage (KARAR_KESİNLEŞTİ / KESİNLEŞTİ).
- No confirmation dialog for stage advancement — action is fast and irreversible by design (D-04). Toast message alone is sufficient.

### 2. STK / Mahkeme Data Forms

- Both forms always visible below their respective stepper (D-05).
- Form uses react-hook-form + zodResolver. Fields are controlled inputs.
- "Kaydet" button at bottom of each form section.
- On save: tRPC `updateSurecDetay` mutation, sonner toast success/error. No page navigation.
- Date fields use the shadcn Calendar popover pattern: Input with calendar icon trigger → Popover → Calendar component. Formatted display: dd.MM.yyyy (tr-TR locale via date-fns).
- All fields optional — no required validation at save time (D-06: independent field saving). Fields accept partial data.

### 3. Mahkeme Section Activation (STK files)

- For `dosya.tur = 'STK'`: Mahkeme section is hidden behind a "Mahkeme Sürecini Başlat" Button (variant="outline") at the bottom of the STK section.
- On click: section expands (no page navigation). A `mahkeme` key is initialized in `surec_detay` JSON via tRPC `initMahkemeSurec` mutation. Button replaced by the full Mahkeme section Card.
- Once activated, the section cannot be hidden again (consistent with D-04: no rollback).
- For `dosya.tur = 'AT'` or `'AH'`: Mahkeme section is always shown; STK section is hidden entirely (AT/AH files never use STK stages).

### 4. Duruşma List

- Sorted: ascending chronological order (earliest date first / most upcoming at top).
- Table columns: Tarih | Saat | Mahkeme/Kurum | Tür | Notlar | Aksiyonlar
- Notlar column: truncated to 40 chars, tooltip on hover shows full text.
- "Düzenle" and "Sil" appear as ghost icon-buttons (Pencil icon / Trash2 icon from lucide-react) in the Aksiyonlar column.
- "Duruşma Ekle" button (variant="default") below the table, left-aligned.
- Empty state: "Henüz duruşma kaydı yok" with "Duruşma Ekle" button inline.

### 5. Duruşma Dialog

- Opens for both add (empty form) and edit (pre-filled form) states.
- Dialog title: "Duruşma Ekle" / "Duruşma Düzenle".
- Form fields order: Tarih (date picker) → Saat (text input, placeholder "09:30") → Mahkeme/Kurum (Select from settings + free text fallback) → Tür (text input, placeholder "esas / ara karar / bilirkişi") → Notlar (textarea, 3 rows).
- Footer: Cancel (Button variant="outline") + Submit (Button variant="default") right-aligned.
- On submit: tRPC `addDurusma` or `updateDurusma`, dialog closes, list refreshes, sonner toast.

### 6. Duruşma Delete Confirmation

- Clicking Sil icon opens AlertDialog: "Bu duruşmayı silmek istediğinizden emin misiniz? Bu işlem geri alınamaz."
- Two actions: "Vazgeç" (outline) and "Sil" (destructive variant).
- On confirm: tRPC `deleteDurusma`, list refreshes, sonner toast "Duruşma silindi."
