# Plan 01-01: Project Scaffold + next.config.ts

## Goal

Bootstrap a greenfield Next.js 15 App Router project with TypeScript strict mode, explicit `serverExternalPackages: ['better-sqlite3']`, all required npm dependencies installed, and environment variables declared — the foundation every subsequent plan depends on.

## Context

This is a completely greenfield project (no existing code). This plan creates the project skeleton before any application code is written. Every other plan in Phase 1 depends on this plan completing successfully.

Critical constraints from RESEARCH.md:
- Install `next@15.5.15` explicitly — `npm install next` now installs Next.js 16 (breaking changes)
- Install `tailwindcss@^3` explicitly — shadcn/ui is incompatible with Tailwind v4
- Use `@trpc/tanstack-react-query` NOT `@trpc/react-query` (legacy)
- `serverExternalPackages: ['better-sqlite3']` is mandatory in `next.config.ts` — without it the native addon fails to load at runtime

<threat_model>
## Security Threat Model (ASVS L1)

### Applicable ASVS Categories
- ASVS 2.10 — Service Authentication: Credentials (SESSION_PASSWORD, APP_PASSWORD) must not be committed to source control
- ASVS 14.2 — Dependency: Pin package versions to prevent supply-chain substitution

### Threats & Mitigations

| Threat | STRIDE | Mitigation |
|--------|--------|------------|
| `.env.local` committed with real secrets | Information Disclosure | Add `.env.local` to `.gitignore`; only `.env.example` (no real values) committed |
| `npm install next` pulls Next.js 16 which breaks the stack | Tampering | Pin `next@15.5.15` explicitly in install command and verify in `package.json` |
| `SESSION_PASSWORD` too short allows iron-session brute-force | Tampering | `.env.example` documents the >=32 character requirement; executor must verify |
</threat_model>

## Verification

```bash
# Verify Next.js version is 15.x
node -e "const p = require('./package.json'); const v = p.dependencies.next; console.assert(v.startsWith('15') || v.includes('15.'), 'FAIL: next version is ' + v); console.log('next version:', v)"

# Verify serverExternalPackages config
node -e "import('./next.config.ts').then(c => { const pkgs = c.default.serverExternalPackages; console.assert(pkgs && pkgs.includes('better-sqlite3'), 'FAIL: better-sqlite3 not in serverExternalPackages'); console.log('PASS: serverExternalPackages =', pkgs); })"

# Verify TypeScript strict mode
node -e "const t = require('./tsconfig.json'); console.assert(t.compilerOptions.strict === true, 'FAIL: strict not true'); console.log('PASS: strict =', t.compilerOptions.strict)"

# Verify critical env vars are declared
node -e "require('dotenv/config'); ['SESSION_PASSWORD','SESSION_COOKIE_NAME','APP_PASSWORD'].forEach(k => { console.assert(process.env[k], 'FAIL: ' + k + ' not set'); console.log('PASS:', k, 'is set'); })"

# Full TypeScript check
npx tsc --noEmit
```

## must_haves

- `next.config.ts` exists and contains `serverExternalPackages: ['better-sqlite3']` — without this better-sqlite3 fails at runtime
- `package.json` shows `next` at version 15.x (not 16.x) — Next.js 16 has breaking API changes
- `tsconfig.json` has `"strict": true` — all subsequent phases depend on strict TypeScript
- `.env.local` declares `SESSION_PASSWORD` (>=32 chars), `SESSION_COOKIE_NAME`, and `APP_PASSWORD` — iron-session and auth will fail without these
- `data/.gitkeep` exists — without the `data/` directory, `drizzle-kit migrate` will fail with SQLITE_CANTOPEN
- `.gitignore` excludes `data/db.sqlite` and `.env.local` — prevent accidental secret/data commits
