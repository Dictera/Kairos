# Plan 01-03: tRPC v11 Route Handler

## Goal

Wire the full tRPC v11 stack: `initTRPC` with superjson transformer, `publicProcedure`, `protectedProcedure` with iron-session auth check, `createCallerFactory`, a root router with a health-check procedure, and the `fetchRequestHandler` route handler at `app/api/trpc/[trpc]/route.ts`.

## Context

Depends on Plan 01-02 (lib/db.ts, lib/schema.ts, drizzle config must exist). The session.ts file does not exist yet — this plan creates `lib/trpc/init.ts` which reads from a `lib/session.ts` that will be created in Plan 01-04. To avoid circular dependencies, this plan creates a minimal `lib/session.ts` stub that Plan 01-04 will expand.

Critical constraints from RESEARCH.md:
- Use `@trpc/tanstack-react-query` (NOT the legacy `@trpc/react-query`)
- `fetchRequestHandler` is the correct adapter for Next.js App Router (not `createNextApiHandler`)
- superjson transformer must be set in `initTRPC.create()` and in the client `httpBatchLink`
- `cookies()` in Next.js 15 is async — always `await cookies()` in the context factory
- `protectedProcedure` reads `session.isLoggedIn` from iron-session

<threat_model>
## Security Threat Model (ASVS L1)

### Applicable ASVS Categories
- ASVS 4.1 — General Access Control: `protectedProcedure` must reject unauthenticated callers with UNAUTHORIZED
- ASVS 13.1 — Generic Web Service Security: tRPC endpoint must only accept POST (fetchRequestHandler handles this)
- ASVS 2.1 — Password Security: Session validation must not leak timing information about session state

### Threats & Mitigations

| Threat | STRIDE | Mitigation |
|--------|--------|------------|
| Unauthenticated caller invokes a `protectedProcedure` | Elevation of Privilege | `protectedProcedure` middleware checks `ctx.session.isLoggedIn`; throws `TRPCError({ code: 'UNAUTHORIZED' })` if false — results in 401 HTTP response |
| `lib/db.ts` imported in tRPC client module (client bundle) | Information Disclosure | tRPC context and procedures are server-only (`lib/trpc/init.ts`); client module (`lib/trpc/client.ts`) only imports types via `typeof AppRouter`, never runtime DB code |
| Serialized session data in cookie tampered to set `isLoggedIn: true` | Tampering | iron-session seals the cookie with SESSION_PASSWORD — tampered cookies are rejected by `getIronSession` at decryption |
| superjson deserializes malicious payload with prototype pollution | Tampering | superjson 2.x does not use `eval` and does not merge into Object.prototype; no additional mitigation required for localhost-only app |
</threat_model>

**lib/trpc/init.ts:**
```typescript
import { initTRPC, TRPCError } from '@trpc/server'
import superjson from 'superjson'
import { getIronSession } from 'iron-session'
import { cookies } from 'next/headers'
import { sessionOptions, type SessionData } from '@/lib/session'

export const createTRPCContext = async (opts: { headers: Headers }) => {
  // IMPORTANT: cookies() is async in Next.js 15 — must await
  const cookieStore = await cookies()
  const session = await getIronSession<SessionData>(cookieStore, sessionOptions)
  return {
    session,
    headers: opts.headers,
  }
}

const t = initTRPC
  .context<Awaited<ReturnType<typeof createTRPCContext>>>()
  .create({
    transformer: superjson,
  })

export const createTRPCRouter = t.router
export const publicProcedure = t.procedure
export const createCallerFactory = t.createCallerFactory

// protectedProcedure: throws UNAUTHORIZED if session.isLoggedIn is false
export const protectedProcedure = t.procedure.use(async ({ ctx, next }) => {
  if (!ctx.session.isLoggedIn) {
    throw new TRPCError({ code: 'UNAUTHORIZED' })
  }
  return next({ ctx: { session: ctx.session } })
})
```

## must_haves

- `lib/trpc/init.ts` uses `transformer: superjson` in `initTRPC.create()` — without this, Date objects are stringified, breaking Phase 4+ date handling
- `createTRPCContext` awaits `cookies()` — required for Next.js 15; synchronous access silently breaks session reading
- `protectedProcedure` throws `TRPCError({ code: 'UNAUTHORIZED' })` when `session.isLoggedIn` is falsy — all future protected procedures depend on this guard
- `app/api/trpc/[trpc]/route.ts` exports both `GET` and `POST` handlers — tRPC uses POST for mutations and GET for queries
- `lib/trpc/client.ts` configures `httpBatchLink` with matching `transformer: superjson` — client and server transformers must match
